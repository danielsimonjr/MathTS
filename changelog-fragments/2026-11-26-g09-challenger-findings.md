### Fixed

- **G09 challenge — indexed assignment that grows a matrix (#1557):** the growth path matches mathjs 15.3.0 (verified: 1-D/2-D/3-D growth, `number: 'BigNumber'`/`'Fraction'` padding, `matrix: 'Array'`/`'Matrix'`, `legacySubset`, scalar/range/`:` growth, Complex/Unit/string entries), but two adjacent parity defects remain inside #1557's scope and are pinned as failing tests in `compat/tests/parity/challenger-g09-findings.test.ts`. **F1:** a column-indexed assignment (`e = [[1,2],[3,4]]; e[:, 2] = [9, 9]`, and its growth form `e[:, 3] = [5, 6]`, 3-D `m[1, :, 1]`) returns the un-reshaped row `[9, 9]` where mathjs returns the column `[[9], [9]]` — the stored matrix is identical on both sides. **F2:** assignment through a zero-length index on an empty matrix (`a = []; a[:] = 5`, `e = []; e[:, 1] = 5`, `a = []; a[1:0] = 3`) must throw in mathjs (`shape mismatch` / `Dimension mismatch`) but silently returns the value on compat, because compat writes a scalar replacement entry-by-entry (a no-op for an empty selection) instead of broadcasting it to the selection shape first as mathjs does.
