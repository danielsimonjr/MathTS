`eigs` of a real symmetric matrix with small entries no longer returns the diagonal (Fixes #1243). The Jacobi stop test in `realSymmetric` now compares against the largest entry of the matrix, so `eigs(c * A)` equals `c * eigs(A)` for number and BigNumber matrices while the entries of `c * A` are normal numbers. The solver runs for a `Matrix` input and for BigNumber entries; a plain number Array uses the native solver and does not change. A zero matrix returns zeros. Prior result for `[[4,1,2],[1,3,0.5],[2,0.5,5]] * c` (true eigenvalues `c * [2.0965, 3.0722, 6.8313]`): number `c = 2^-60` gave `[2.602e-18, 3.469e-18, 4.337e-18]` (the diagonal sorted, no rotation); number `c = 2^-600` gave `[7.23e-181, 9.64e-181, 1.205e-180]`; BigNumber `c = 1e-18` gave `[3e-18, 4e-18, 5e-18]`; BigNumber `c = 1e-1000` gave `[3e-1000, 4e-1000, 5e-1000]`. Results for `c = 1` are unchanged. For `c = 2^60`, `2^600`, `1e18` and `1e1000` the eigenvalues are unchanged; the eigenvectors now stop at the same relative tolerance as for `c = 1` (largest relative residual of 200 random matrices at `c = 1e200`: 3.1e-13, was 3.9e-15, because the absolute tolerance made a large matrix rotate further).

A graded matrix, where a small diagonal block sits beside large entries, now keeps its small eigenvalues: after the scale test, each pair rotates until `|a_ij| <= prec * sqrt|a_ii| * sqrt|a_jj|` (floored at rounding noise), and the equal-diagonal test compares against `|a_ij|`. Prior result for `[[1,0,0],[0,1e-12,1e-13],[0,1e-13,1e-12]]` (true eigenvalues `0.9e-12, 1.1e-12, 1`) was `1e-12, 1e-12, 1` for number and BigNumber; mathjs 15.2.0 gives the same wrong result. No tolerance is below the rounding error of one rotation, so a subnormal matrix and a `precision` of 0 terminate (a `precision` of 0 did not return for a 6 x 6 matrix with repeated eigenvalues).

Behaviour change: `eigs` now throws a `RangeError` for a `Matrix` or a BigNumber or Complex input with a NaN or Infinity entry, symmetric or not. Before, it returned values that did not depend on the bad entry (for example `[1, 2]` for `matrix([[1, NaN], [NaN, 2]])` and for `matrix([[1, NaN], [3, 2]])`, and `[-Infinity, Infinity]` for an Infinity entry), as mathjs 15.2.0 does. A plain number Array already threw a `RangeError` (#989).
