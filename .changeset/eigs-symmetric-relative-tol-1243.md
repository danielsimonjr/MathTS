`eigs` of a real symmetric matrix with small entries no longer returns the diagonal (Fixes #1243). The Jacobi stop test and the equal-diagonal test in `realSymmetric` now compare against the largest entry of the matrix, so `eigs(c * A)` equals `c * eigs(A)` for number and BigNumber matrices. A zero matrix returns zeros. Prior result for `[[4,1,2],[1,3,0.5],[2,0.5,5]] * c` (true eigenvalues `c * [2.0965, 3.0722, 6.8313]`): number `c = 2^-60` gave `[2.602e-18, 3.469e-18, 4.337e-18]` (the diagonal sorted, no rotation); number `c = 2^-600` gave `[7.23e-181, 9.64e-181, 1.205e-180]`; BigNumber `c = 1e-18` gave `[3e-18, 4e-18, 5e-18]`; BigNumber `c = 1e-1000` gave `[3e-1000, 4e-1000, 5e-1000]`. Results for `c = 1`, `2^60`, `2^600`, `1e18` and `1e1000` are unchanged.

A graded matrix, where a small diagonal block sits beside large entries, now keeps its small eigenvalues: after the scale test, each pair rotates until `|a_ij| <= prec * sqrt|a_ii| * sqrt|a_jj|` (floored at rounding noise), and the equal-diagonal test compares against `|a_ij|`. Prior result for `[[1,0,0],[0,1e-12,1e-13],[0,1e-13,1e-12]]` (true eigenvalues `0.9e-12, 1.1e-12, 1`) was `1e-12, 1e-12, 1` for number and BigNumber; mathjs 15.2.0 gives the same wrong result. `eigs` now throws a `RangeError` for a matrix with a NaN or Infinity entry; before, it returned values that did not depend on the bad entry (for example `[1, 2]` for `[[1, NaN], [NaN, 2]]`).
