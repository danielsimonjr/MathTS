Integer functions follow mathjs for BigNumber and edge arguments. `nthRoot(bignumber(-8), 2)` throws `Root must be odd when a is negative.` (it returned NaN). `permutations` takes one BigNumber, two BigNumbers, and a BigNumber with a number; the result is the exact product, rounded one time to the precision. `permutations(2, 5)` and `permutations(-1, 2)` throw the mathjs messages. `permutations(170)` and `permutations(170, 170)` are `7.257415615307998e+306`, as in mathjs. `permutations` of an Array or a matrix maps over the elements (mathjs throws). `product` splits a range at an exact midpoint, so `permutations(2^53, 2)` returns `8.112963841460667e+31` where the parse path overflowed the stack. `bitAnd`, `bitOr`, `bitXor`, `bitNot`, `leftShift` and `rightArithShift` of BigNumbers return a BigNumber NaN when an operand is NaN, as mathjs does; before, they threw `NaN not allowed`. A finite non-integer operand still throws `Integers expected`, and `rightLogShift` still throws for NaN. On the parse path, and on `evaluate` of `bitAnd` and `bitOr`, a finite BigNumber operand threw `Cannot read properties of undefined`, because the helpers read the digit array of decimal.js, which a BigNumber of this library does not have; and `bitNot(bignumber(12))` returned `13`, because the helper wrote a sign field that the BigNumber does not store (`bitXor(-1, bignumber(5))` gave `6`). The helpers now compute on bigint: `bitAnd(bignumber(12), bignumber(10))` is `8`, `bitNot(bignumber(12))` is `-13` and `bitXor(bignumber(-1), bignumber(5))` is `-6`, as in mathjs.

The return type of a call with one BigNumber and one number changes: `permutations(bignumber(10), 3)` and `permutations(10, bignumber(3))` return BigNumbers, as mathjs does. Before, they returned numbers. (Refs #1097)
