The binaries `mathts.wasm` and `mathts-debug.wasm` of the package have no import any more. The build sets `use: ["abort=src/abort/trapAbort"]` in `asconfig.json`, so an abort calls a function of the binary that traps, and no host function `env.abort` is necessary. Node reads each import of a WebAssembly module as a package name, so `import('@danielsimonjr/mathts-wasm/wasm')` failed with `ERR_MODULE_NOT_FOUND`. Now Node loads both binary subpaths as WebAssembly ES modules (Node 22.12 needs `--experimental-wasm-modules`; Bun returns the file path as `default`), and any runtime instantiates them with an empty import object. The subpaths `./wasm` and `./debug` have a `default` condition, so `require.resolve` finds the files. The new subpath `./debug.js` exports the glue of the debug build. An abort stores its message, file, line and column in globals of the binary (new exports `abort_take`, `abort_message`, `abort_file`, `abort_line` and `abort_column`) and traps as `WebAssembly.RuntimeError`. The glue turns the trap into `Error('<message> in <file>:<line>:<column>')`, the text of before. `functions` and `matrix` ship the rebuilt binary (62928 bytes, no import). `@danielsimonjr/mathts-core` exports `guardWasmAborts`, `translateWasmAbort` and `WASM_ABORT_TEXT` from `/internal`, and the loaders of `matrix` and `functions` use them. An abort that a call of their WASM tier reaches is the same `Error` as before (`WASM abort`; `AS WASM abort` from `WASMBackend`), and its `cause` now holds the message and the position of the abort. The loaders no longer print a `console.error` line for an abort. Their `getImports()` is empty. (Refs #1019)
