**Breaking (output text):** every CAS function that returns a polynomial as text now writes the one canonical form: descending lexicographic order (the first variable is the most significant) and no unit coefficient. `expand('(x+1)^2')` is `x^2 + 2*x + 1`; it was `1 + 2*x + 1*x^2` (#887). The same text now comes from `casExpand`, `factor`, `cancel`, `together`, `apart` and `groebnerBasis`: `expand('(x+y)^2')` is `x^2 + 2*x*y + y^2`, `factor('x^2*y + x*y^2')` is `x*y*(x + y)`, and `groebnerBasis(['x^2-y', 'x*y-1'], ['x', 'y'])` is `['x - y^2', 'y^3 - 1']`. `collect` and `minimalPolynomial` use it too: `collect('x^2-3*x+1', 'x')` is `x^2 - 3*x + 1` (it was `x^2 + -3*x + 1`), and `minimalPolynomial('sqrt(2)', 'x')` is `x^2 - 2` (it was `10*x^2 - 20`). `integrate('3*x^2', 'x')` is `x^3` (it was `1*x^3`). The rational-function integrators share the printer too; a leading negative term there prints `-x^2 + 1`, not `- x^2 + 1`. Code that compares these strings with the old text must change. The value of each result is the same.

The printer never writes a term with a zero coefficient (`-0*x`), and it throws a `TypeError` for two terms with the same exponent vector. A coefficient with an exact fraction keeps it: `expand('x/3 + 1/2')` is `1/3*x + 1/2` (it was `0.333333333333*x + 0.5`). A polynomial whose fractions all have a finite decimal keeps the decimals (`0.5*x + 0.25`). `expand` keeps a small coefficient (`1e-13*x^2`, `1e-11*x`); it dropped every coefficient below `1e-10`. It reads the residue of a cancellation as zero when the residue is small next to the terms that made it (`x + 1e-5*x - x - 1e-5*x` is `0`). `expand` throws a `PolynomialDegreeError` (a `RangeError`) for a polynomial of a degree above 1000, so `expand('(x^0)^1000000000*x')` and `expand('(x+1)^1000000000')` end at once; before, they ran for a long time. `toRadicals` returns `[]` for an expression that is not a polynomial (`toRadicals('sin(x)')` returned invented roots).
