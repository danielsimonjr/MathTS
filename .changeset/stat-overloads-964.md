The public types of `median`, `mode` and `mad` give the number type for a `readonly number[]` argument, and `median('x')`, `median({})`, `median()`, `mad()`, `mode()` and `mode(array, 0)` are compile errors. A spread of a plain array (`median(...xs)`) no longer compiles: pass the array. `matrix()` and `sparse()` return the new public type `BridgeMatrix`, and `bignumber()` of a scalar returns `BigNumber`. So `median`, `mode`, `mad`, `mean`, `variance` and `std` of `matrix(x)` compile. The statistics functions take the new public type `MatrixValue`. Compat `matrix()` and `sparse()` return the same `BridgeMatrix`. At run time, `mode` of a Matrix inside the argument list throws a `TypeError` in place of the false NaN message. `parallelFFT`, `parallelConv`, `parallelXCorr`, `parallelAutoCorr`, `dct`, `dst`, `hilbertTransform`, `polymul`, `newtonInterp`, `polyFit` and the other callers of the shared sample copy throw a `TypeError` for an array entry with no numeric reading (a nested array such as the column `[[1], [3], [5]]`, an object, `undefined`, a string that is no number). A BigNumber, a Fraction and a numeric string entry still convert, and `''`, `' '`, `true` and `null` read as 0, 0, 1 and 0. `parallelStatStd` and `parallelStatVariance` throw the `TypeError` of `std` for an unknown normalization string. (Refs #964, Refs #1359)
