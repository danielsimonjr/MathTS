**Breaking:** `solve` returns the exact solution set. It scans for roots numerically only when you pass `{ numeric: true, range: [a, b] }` (#884). `solve('sin(x)=0', 'x')` returned 63 floating-point roots in `[-31π, 31π]`. It now returns `['0', 'pi']` with a `period` property of `'2*pi'`: the principal roots of one period; add `k * period` for all roots. An equation `a*F(p*x + q) = b` with `F` one of `sin`, `cos`, `tan`, `exp`, `log`, `sqrt` or `abs` gets exact text roots: a multiple of `pi` for a special value (`sin(x) = 1/2` is `['pi/6', '5*pi/6']`), a symbolic inverse for another value (`sin(x) = 1/3` is `['asin(1/3)', 'pi - asin(1/3)']`). The roots are real roots: `sin(x) = 2` is `[]`. The coefficient of `x` may be a fraction of `pi`: `sin(2*pi*x) = 0` is `['0', '1/2']` with `period` `'1'`. No root text holds a rounded digit, so a constant with no exact text (`sin(x) = sqrt(2)/3`, an offset of `pi/4`) throws like any form with no closed form. `solve` reads the polynomial from the syntax tree, not from sample values: `sin(2*pi*x) = 0` returned `[]` and `x^3 - e` returned `NaN` before. Any other form with no closed form (`sin(x) = x`, `sin(x)^2 = 1/4`, `1/x = 2`) throws an `Error` that names the numeric option; before, it returned scanned floats. A polynomial of degree 4 or more now returns all its distinct real roots by Sturm isolation (`realRoots`) over the whole real line, not from a fixed scan window of `[-100, 100]` and `[-1000, 1000]` that missed a root outside it. The result of the scan is sorted and stays inside `range`. Exports the types `SolveOptions` and `SolveResult`.
