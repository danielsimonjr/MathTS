A matrix decomposition throws for a nested array that is not two dimensional. Before, `qr`, `qrPivoted`, `lu`, `cholesky`, `svd`, `lq`, `rq`, `ql`, `eig`, `lstsq`, `condest`, `matrixSchur` and the other functions that take a nested array checked each row and not its entries. They returned a factorization of `[[[1], [2]]]`, of two 2 x 2 layers and of a row that mixes numbers and Arrays. Now a tensor throws `RangeError: Matrix must be two dimensional (size: [1, 2, 1])`, and a row that mixes numbers and Arrays throws the jagged `TypeError` of that row. An `undefined` entry (a hole, or a missing value) throws `TypeError: Matrix decomposition: nested array must contain numbers; row 0 column 1 is undefined`; before, `[[1, undefined], [2, 3]]` and `[[1, 2], [3, ,]]` gave a factorization full of NaN. An entry of another type still passes this check, because `lusolve` reads a BigNumber, a Complex, a Fraction or a numeric string entry on its typed path. (Refs #1260)
