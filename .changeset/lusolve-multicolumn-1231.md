`lusolve` throws `RangeError: Dimension mismatch` for a right-hand side of more than one column, on every input kind (Fixes #1231). `lusolve`, `lsolve` and `usolve` solve one column vector, as in mathjs. Before, `lusolve([[2,1],[1,3]], [[1,2],[3,4]])` with an Array `A` returned `[[0],[1]]`, the solution of column 1 only, and dropped column 2. This held for an Array, DenseMatrix or SparseMatrix `b`. A DenseMatrix or SparseMatrix `A` already threw `Dimension mismatch`. With an Array `A`, two more malformed `b` values now throw instead of returning a wrong result: a ragged `b` such as `[[5],[10,1]]` (before: `[[1],[3]]`), and a 1×2 `b` for a 1×1 `A`, such as `lusolve([[2]], [[4,5]])` (before: `[[2]]`). A `b` with an Array entry also throws now: `[5, [10]]`, `[[[5]], [[10]]]` and a 3-D DenseMatrix `b` returned `[[1],[3]]` before, and `[[5], 10]` and `[[5], []]` returned `[[NaN],[NaN]]`. With an Array `A`, a 1-D DenseMatrix `b` of the wrong length and a 1×n row DenseMatrix `b` (n ≥ 2) already threw a plain `Error` (`luSolve: right-hand side length ...`). They now throw `RangeError: Dimension mismatch`. A 1×n row Array `b` already threw that `RangeError`.
