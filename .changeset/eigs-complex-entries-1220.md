`eigs` of a matrix with Complex entries keeps the imaginary part of each entry (#1220). The factory scope `complex(x)` built `new Complex(x, undefined)`, so a Complex argument became a Complex that held the entry in `re`, and `abs` read it as its modulus. `complex()` now follows mathjs: no argument or `null` gives 0, it clones a Complex, and it accepts a number, BigNumber, Fraction, bigint, boolean, string, `{re, im}`, `{r, phi}`, `{abs, arg}` and an Array. Before: `eigs([[complex(2,1)]])` gave 2.236 (now 2+i); `eigs([[complex(0,1),0],[0,1]])` gave 1, 1 (now i, 1); `diag(2+i, 5+i)` gave 2.236, 5.099 (now 2+i, 5+i); `[[2+i,1],[0,3]]` gave 2.236, 3 (now 2+i, 3); `[[2,1-i],[1+i,3]]` gave 0.9999999999999991, 4.000000000000001 (now 1.0000000000000002, 4, within 1e-8 of 1 and 4, as mathjs 15.2.0). The public `complex(complexValue)`, `complex({re, im})` and `complex('2+i')` returned a Complex that held the argument in `re`; they now return the Complex. `complex(Matrix)` maps each entry and returns a Matrix. A part of `(re, im)` that is not a number, BigNumber, Fraction, bigint, boolean or numeric string throws a TypeError, as do a single argument of another type (`complex(undefined)`) and a third argument, as in mathjs. `complex(1, undefined)` returned 1 and now throws. The parts of an object convert to numbers. The call shape `(value, index, collection)` converts the value, so `[1, 2].map(complex)` gives 1 and 2. The compat `complex` shim uses the functions `complex` for every input except no argument and a single Complex, which it still returns unchanged; `complex(z, 5)` returned `z` and now throws a TypeError, and a third argument throws.
