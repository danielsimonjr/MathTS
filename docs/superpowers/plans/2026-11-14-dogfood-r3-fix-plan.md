# Dogfood round 3: fix plan (reviewed)

This plan fixes each open issue at the root cause. The scope is the 68 open issues of `danielsimonjr/MathTS` at `fb43921c` and the 57 tests that the Node test run does not run (functions 53, matrix 4, in `tools/test/skip-baseline.json`).

Fault sites come from `C:/Users/danie/mathts-dogfood-r3/loc-{a,b,c,d,e}-final.md`. Each worker reads the cited lines before the worker writes code. A cited line that does not match the source stops the task: report the mismatch.

## 1. Rules for each task

1. Write the failing test first. Confirm that the test fails on `main`. Then change the code.
2. A task that starts with "Repro first" runs the repro at `main`. If the repro passes, add the pin test only and make no code change.
3. Fix the shared helper, not one export. Add one test row for each sibling that the task lists.
4. Do not widen a limit. Do not skip or delete a test. Do not catch and ignore an error.
5. Put a new helper in an existing file. A new `.ts` file needs `npm run docs:deps` before the commit.
6. A worker does not edit these files: `CHANGELOG.md`, `docs/Architecture/*` generated reports, `tools/test/export-lock.json`, `functions/types/public-overloads.generated.d.ts`. The fixer regenerates them after the rebase of each PR.
7. Add a changeset for each changed package. A breaking change is a `minor` changeset (all packages are 0.x). A breaking change is permitted only where section 3 says that no non-breaking fix exists.
8. Run the focused tests, then `bun run typecheck`, `bun run lint` and the package suite. A test of one package reads the built `dist` of its dependencies: rebuild a changed dependency first.
9. Oracle values in a test are literals from this plan, a brute-force computation in the test, or a call to `mathjs` 15.2.0 in the test. Do not write a constant from memory.
10. An error for a bad argument is a `TypeError` (wrong type) or a `RangeError` (wrong value). The message names the function, the argument and the accepted input.

## 2. Relay route and merge order

| Role             | Model  | Effort  |
| ---------------- | ------ | ------- |
| Worker           | Haiku  | low     |
| Challenger       | Haiku  | low     |
| Checker          | Haiku  | low     |
| Reviewer         | Sonnet | low     |
| Fixer and merger | Opus   | default |

- A task marked **[S]** starts on Haiku. After one failed check it moves to a Sonnet worker.
- Each task is one PR in its own worktree.
- A lane (section 5) is a list of tasks that share files. Tasks in one lane run in the listed order. Different lanes run in parallel.
- An `After:` field is a dependency on a task in a different lane. Do not start the task before that dependency is merged.
- The fixer merges one PR at a time: rebase, regenerate the files of rule 6, wait for all checks to pass, merge.

## 4. D17: the four fix classes

Each function in the #989, #990 and #1001 lists gets the first class that applies.

1. **Not an exact integer.** A count argument above `Number.MAX_SAFE_INTEGER` throws a `RangeError`. The loop counter cannot step above 2^53, which is the cause of the hang. Model: `nextPrime` (`functions/src/typed/combinatorics.ts:336-338`).
2. **The result is known without the loop.** Return it in O(1) or O(log n): an overflow to `Infinity` (stop a product loop when the result is not finite), `lgamma` for `multinomial` and `permutations`, fast doubling for `lucasL`, Newton steps on `bigint` for `integerSqrt`, the asymptotic series for `harmonicNumber` above 1e6.
3. **Memory.** An allocation above `DENSE_MATRIX_MAX_ELEMENTS` (`matrix/src/types/dense/limits.ts:6`) throws a `RangeError` before the allocation. Compute the product by division, as `limits.ts:24-26` does. Applies to `zeros`, `ones`, `resize`, `hadamardMatrix`, the sieve, and the `bernoulli`, `stirlingS2` and `bellNumbers` caches.
4. **A true O(n) recurrence** (orthogonal polynomials, Bessel order, filter order, `binomialTest`). One named constant `MAX_RECURRENCE_ORDER = 1e7` in the limits module, with a comment that states the cost per step. Above it: `RangeError`. The value is a design constant. It is not measured on CI.

All constants are in one module, `core/src/numeric/limits.ts` (new file; rule 5 applies). It holds `DENSE_MATRIX_MAX_ELEMENTS` and `MAX_RECURRENCE_ORDER` and exports `assertCount(n, fn, arg, max)` and `assertElementCount(dims, fn)`. `matrix/src/types/dense/limits.ts:6` imports the constant from core and keeps its own export, so the value has one definition.
