# MathTS parity review against NumPy, SciPy, PySR, Mathematica, MathCad and MATLAB

## Sources of truth

MathTS cannot run Mathematica, Mathcad, or MATLAB to check results. For
correctness of numeric and symbolic output, the sources of truth are
**NumPy**, **SciPy**, **SymPy**, and **PySR**.

Mathematica, Mathcad, and MATLAB are **feature references only**. They
inform API shape and feature-coverage decisions. They are never used to
verify numeric or symbolic output.

Where this report, or a companion deep review, treats a closed system's
documented or observed behavior as expected output — including GNU Octave
stand-in values used in place of MATLAB — that expectation is
**unverified** until it is confirmed against NumPy, SciPy, SymPy, or
PySR.

Generated on Wed Nov 25, 2026 (America/Chicago). This review is read-only: nothing was pushed, and no issues or PRs were opened.

## 2. Method

1. **Reference inventories** were built by programs, not from memory: `scripts/enum_py.py`, `fetch_mw.py`/`parse_mw.py` (Playwright, because MathWorks returns 403 to curl), `parse_ptc.py`, and the WL guide scrape. Every item was classified into one of 26 areas or marked out of scope (`scripts/classify.py`).
2. **The MathTS inventory** comes from three sources:
   - A runtime `import()` of every package entry point. This collects class prototype methods and the keys of the `compat` instance.
   - A ripgrep of `export` lines across every `*/src`.
   - The docs: `docs/plans/SYMBOLIC_REGRESSION_EXPANSION_PLAN.md`, `docs/reference/scalar-search.md` and `docs/roadmap/GAP_ANALYSIS_2026-11-04.md`.
3. **Name-level matching** ([`ref_name_match.csv`](2026-11-25-six-system-parity/data/ref_name_match.csv)) uses normalised lowercase alphanumeric names and is a **lower bound only**: NumPy 22%, SciPy 17%, MATLAB 19%, Mathematica 16% and MathCad 19% of in-scope names. Naming conventions differ too much across these systems for it to be the main measure.
4. **The primary instrument is 274 curated capability rows** (`scripts/concepts.py`). Each row merges the equivalent names from every reference. `scripts/build_gaps.py` then does three checks:
   - It validates every cited reference name against the scraped inventories. 2405 of the 2624 cited names validated. The 219 that did not, mostly MATLAB Control/DSP/Image toolbox names and WL symbols outside the 45 guides, are **dropped from the counts**; they are listed in `out/build-issues.txt`.
   - It validates every MathTS name against the runtime exports. Rows that claimed coverage but had no export found were automatically downgraded, then fixed by hand using the real export names.
   - For every _missing_ row, it runs a regex grep of MathTS source. All 11 rows with grep hits were reviewed by hand: they were internal helpers, comments or false positives, recorded in each row's `notes`.
5. **Status** is one of:
   - `full`: the capability and the named API are exported.
   - `partial`: some of it is exported, and the row's `notes` lists what is not.
   - `missing`: no export, confirmed by the export check and the grep.
6. **Priority** is set by how many of the five general systems (NumPy, SciPy, MATLAB, Mathematica, MathCad) have the capability, counting validated names only:
   - **P0**: 4 or more systems.
   - **P1**: 2–3 systems.
   - **P2**: 1 system.
   - Symbolic-regression rows are compared with PySR and given hand-set priorities.
7. **Runtime verification** (`verify/`): 49 MathTS calls were compared with NumPy/SciPy/SymPy on fixed inputs. One more call confirmed the polynomial-root gap: the function fails as expected.

## 5. Where MathTS is ahead

- **Autodiff** is built in, with both a reverse-mode tape and forward dual numbers (`grad`, `reverseGrad`, `forwardGrad`, `TapedTensor`, `DualTensor`). NumPy, SciPy and MathCad have none, and MATLAB has it only in its Deep Learning toolbox.
- **Exact and enclosure arithmetic** is everywhere: BigNumber, Fraction and Interval.
- **Exact rational linear algebra**: `rationalNullspace`, Hermite and Smith normal forms.
- **Physics special functions**: Wigner 3j/6j, Clebsch–Gordan, Mathieu, spheroidal and Coulomb wave functions. SciPy and MATLAB lack Wigner symbols, and MATLAB lacks most of the rest.
- **Robust geometric predicates** (`orient2D`, `inCircle`), plus spherical Voronoi and halfspace intersection.
- **Effect sizes** (Cohen's d, Hedges' g, η², Cohen's κ) and `tTestPower`. SciPy has no effect-size module.
- **Statistics extras**: circular statistics, `energyDistance`, `wassersteinDistance` and `hausdorffDistance` as first-class functions.
- **Units** with an exact-scale table and SI dimension vectors. Units are absent from NumPy and SciPy and an add-on in MATLAB.
- **Symbolic regression with a hard dimensional-consistency filter** (SR-9). PySR only applies a soft penalty.
- **Browser and edge execution**: WASM kernels, WebGPU, a worker pool, and the workbook notebook format with a CLI.
- **Control matrix equations** (`care`, `dare`, `lyap`, `dlyap`, `sylvester`) are built in. MATLAB needs the Control System Toolbox for these.

## 8. What was NOT verified (honesty list)

- **Reference completeness.**
  - MATLAB covers only the six requested product lists. Names from Control, DSP, Image, Wavelet, Econometrics, Global Optimization and PDE toolboxes did not validate and were **dropped from counts**, so MATLAB support is under-counted for notch filters, `dwt`, `lyap`/`care`, `imfilter`, `gamultiobj` and similar.
  - Mathematica covers 45 guide pages (1345 symbols), not the full ~6,000-symbol language. Symbols such as `ToeplitzMatrix`, `HannWindow` and `LinearProgramming` exist in Wolfram Language but were not in the scraped guides, so they were dropped. There are 219 unvalidated names in total (`out/build-issues.txt`).
  - The MathCad TOC parse missed some names. They were supplemented from their own pages (`out/mathcad-supplement.json`). Deprecated MathCad functions (e.g. `regress`, `medfilt`, `cfft`) were excluded.
- **PySR was not executed.** The Julia backend install hung, so the PySR inventory comes from source and AST. There is no head-to-head SR accuracy or speed benchmark.
- **Depth is not measured.**
  - `full` means the capability and its named exports exist. It does not mean every option of the reference API (e.g. `solve_ivp` `t_eval`/`vectorized`, distribution `loc`/`scale` semantics).
  - Symbolic depth (integrate, dsolve, simplify quality) was not compared against SymPy or Mathematica.
  - Units semantics, WASM/GPU paths and performance were not tested.
- **Runtime sample size.** Only 49 functions were checked, on one or two benign inputs each. There are no edge cases, complex arguments, large or ill-conditioned inputs, or NaN/Inf handling. 225 of the 274 rows rest on export plus grep evidence only.
- **Curated rows.** The 274 capability rows were written by hand. A capability absent from every row is invisible to this review. Area totals depend on how finely rows were split. Use [`ref_name_match.csv`](2026-11-25-six-system-parity/data/ref_name_match.csv) for an exhaustive (lower-bound) per-name view.
- **Moving target.** The MathTS inventory is from `main` @ 76f7a5b and its build at 06:12 CT today. The mathjs-parity A-Team is changing MathTS concurrently, so some rows (especially ndarray and compat-adjacent ones) may change soon.
- **Priority counting** uses validated names only, so a capability present in a reference but absent from the scraped inventory may be under-prioritised (e.g. `ToeplitzMatrix` in WL).
- **Grep coverage.** "Missing" grep checks use row-specific regexes over `*.ts`, excluding tests, dist and `.d.ts`. A capability implemented under an unexpected name would be missed by both the regex and the export check.
