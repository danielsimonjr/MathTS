# Export Triage (WS-3 Phase 1 — classification only)

**Date:** 2026-07-02
**Source:** `docs/Architecture/unused-analysis.md` — 452 "potentially unused exports"
(exports not _imported_ by any other file in the codebase).
**This document makes no code changes.** It is a classification work-list for the
eventual WS-3 Phase 2 (internalize) and Phase 2b (delete) commits.

## The critical caveat

"Unused **internally**" is **not** the same as "not public API." The analysis tool
counts an export as unused when no other file _imports_ it — but a symbol that is
**re-exported from its package's public `src/index.ts`** (directly or transitively
via `export * from './sub/index.js'`) is the package's published surface and is
**not dead**. A very large fraction of the 452 are exactly this: return-type
interfaces, option bags, and config/typed-function types that end users need but
that no _other source file_ happens to import. Those are KEEP (or PROMOTE), never
DELETE.

Every classification below was made by reading each package's barrel + sub-barrels
and grepping the `src/` tree **and** the `tests/` trees for real consumers.

## Buckets

- **PROMOTE** — genuinely useful, user-facing functionality (or the option/return
  type of a public function) that is _not_ currently reachable from the barrel but
  clearly _should_ be. Action: wire into `src/index.ts` and add to the curated
  tables in `docs/reference/functions.md`.
- **KEEP** — already public API (a re-export "unused"-flagged false positive) **or**
  a test-only / instance-registered helper that is legitimately alive. Leave as-is;
  no doc action required (these are types/config/plumbing, not new math functions).
  This is the "or leave-as-is" outcome the caveat calls out.
- **INTERNALIZE** — a real internal helper/type/duck-shim/factory-piece/JS-fallback
  that leaks from the surface but is _not_ reachable from the barrel and is not
  meant for end users. Action: mark `@internal` (or move behind a `/internal`
  subpath). **Not deleted** — most have in-file or test consumers.
- **DELETE** / **DELETE?** — no consumer anywhere (not re-exported, not composed
  in-file, not tested), superseded/leftover. `DELETE?` = high-confidence-dead but
  wants one human confirmation before removal. A wrong DELETE is worse than a
  wrong UNSURE, so borderline items are marked `DELETE?`.
