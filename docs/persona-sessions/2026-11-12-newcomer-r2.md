# Newcomer TypeScript developer — npm README dogfood, round 2 (2026-11-12)

I have never used MathTS. I did not build the monorepo. I made a fresh ESM
project at `/tmp/mathts-newcomer-r2` on Node v22.23.4 (TypeScript 5.7.3, `strict`,
`moduleResolution: NodeNext`) and installed all **24** published `@danielsimonjr/mathts-*`
packages from npm at the versions pinned in the round-2 persona brief (release
cb254e81, published 2026-11-12). `npm ls --depth=0` matched every expected version.

I learned from npm READMEs, the repo README, `docs/`, and the public site
[danielsimonjr.com/MathTS](https://danielsimonjr.com/MathTS/). I did **not** fix
anything in the codebase.

Duplicate reports: GitHub returned **403 Resource not accessible by integration**
when I tried to comment on closed issues or open duplicates (#883, #715); I filed
new issues where needed instead.

## Goal

Follow each package’s npm README top to bottom, run every TypeScript fence with
`tsx`, typecheck fences with `skipLibCheck: true`, and compare README / exports /
`.d.ts` / runtime. Re-verify round-1 newcomer issues (#789–#804 and related).
Keep a per-package pass/fail table and compare with
[round 1](./2026-11-11-newcomer.md).

## What I tried, in order

1. Installed all 24 scoped packages at pinned versions; confirmed `npm ls`.
2. Ran an automated harness: extract every ` ```typescript` / ` ```ts` fence from
   each npm README, execute with `tsx`, typecheck with `tsc`.
3. Re-ran round-1 repro scripts (LICENSE tarball, `Tensor.fromNested`, evaluator
   `compileExpression`, signal `fft`, `createParse`, linalg `DenseMatrix`, landing
   page version, `/MathTS/api`, root Quick Start).
4. Read repo README install table and Quick Start; ran compat + typed + pool paths.
5. Checked packaging: LICENSE in tarball, `homepage` / `bugs` on `package.json`
   (all 24 now present).

## Getting-started path (root README)

With all consumer packages installed, root Quick Start **(a)** compat and **(b)**
typed paths run: `3 1 13`, `add(1,2)`, `evaluate('2^10')===1024`, `await loadWasm()`
prints success. **(c)** `computePool` sum/matmul/terminate works. README generated
block still says functions **0.84.0** while npm is **0.85.0** (part of #917).

`skipLibCheck: false` on a project that imports `@danielsimonjr/mathts-functions`
still fails on transitive `@danielsimonjr/mathts-gpu` WebGPU ambient types (and
related open regressions).

## Verdict

Round-1 packaging fixes (**LICENSE**, **homepage**, most README samples,
evaluator/tensor/signal/function exports) **landed on npm** and make the library
much easier to try from Quick Start. Remaining newcomer pain: **public docs still
stale/offline** (#917, #919), **parser factory regression** (#883), **parallel/plot
README fences that assume Vite or a browser**, **strict typing on signal FFT**, and
**linalg/matrix import split** (#915). Compared to round 1, README coverage is
dramatically better (35 fences vs 17, one package without a sample vs twelve).
