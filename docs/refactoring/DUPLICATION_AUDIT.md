## Highest-value consolidation opportunities (top 5)

1. **Unify the special-function scalar core (Cluster A).** Extract one canonical scalar module; have the special bridge import it and have `typed/special.ts` reference it — eliminates ~420 LOC of duplicated JS *and* the scalar-vs-array drift risk. **Risk: medium** — must preserve the worker-serialization constraint (typed kernels are `.toString()`-serialized, so the shared scalars must stay self-contained / no module-level state, or the kernel-builder must inline deps).
2. **Codegen/generic-ify the bridge dispatch (Clusters C+D).** A shared `bridges/common.ts` with `getWasm()`, the Rust fn-type aliases, and a `makeDispatch(rustName, asName, jsFallback, arity)` factory collapses ~7×N copies of the alloc/release/probe pattern. **Risk: low-medium** (leave elementwise's scratch-region path as-is). **→ fold into Rust→AS migration Phase 3 (bridge rework).**
3. **Extract `matrix/src/operations/common.ts` (Clusters F+G).** Move `cloneMatrix`, `eye`, `applyHouseholder*`, `isSymmetric`, and the dense `matMul/matAdd/…/norms`; parameterize `householder(beta)` so schur keeps β=2. **Risk: medium** (must not flatten the deliberate schur divergence).
4. **~~Dedupe core type guards onto `is.ts` (Cluster I).~~ DONE 2026-06-26 — and the original plan was wrong.** Caller audit showed `types/*.ts` (not `is.ts`) are the *exported canonical* guards; `is.ts` is dormant synced-mathjs. So nothing was collapsed onto `is.ts`. Instead the lone active hazard — `core/src/utils.ts`'s same-name `isComplex`/`isMatrix` (structural / `number[][]`) — was renamed to `isComplexLike`/`isMatrixArray`. See the Cluster I row and the 2026-06-26 CHANGELOG entry.
5. **Single parallel-map util (Cluster E) + shared `rowMajorStrides` (Cluster H).** Hoist `mapArray`/`kernelSource` to one helper imported by special+distributions; export `rowMajorStrides` from tensor for autograd/parallel. **Risk: low.**

## Checked but NOT duplicated (don't re-investigate)

- **Carlson RC/RF/RD/RJ and incomplete elliptic F/E/Π have a single JS home** in `functions/src/wasm/special/wasm-bridge.ts` (`_carlsonRC`563 … `_ellipticPiIncomplete`723, `*Scalar` exports 785-791). `typed/special.ts` *imports* these (lines 41-54) rather than re-implementing — no JS copy. (AS/Rust mirrors = intentional cross-language, Cluster B.)
- **`elementwise/wasm-bridge.ts` is NOT the same boilerplate** as the other bridges: it manages its own `scratchBase` memory region (lines 60-94) and never uses `wasmLoader.allocateFloat64Array`/`release`. Distinct by design.
- **`mapArray`/`kernelSource` appear only in special.ts + distributions.ts** — arithmetic/trigonometry/statistics/signal typed files use other dispatch shapes.
- `flattenMatrix` (`matrix/src/operations/eig-wasm.ts:49`) — single definition.

## Cross-reference: Rust→AS migration

Clusters **C + D** (bridge `getWasm()` + per-kernel dispatch boilerplate) and **J** (poly resultant/discriminant) live in the 6 bridges that the Rust→AS migration Phase 3 rewrites. Consolidation Opportunity #2 should be **executed as part of Phase 3**, not separately — the bridge rewrite to the AS ABI is the natural moment to replace the duplicated dispatch boilerplate with a single `makeDispatch` factory. Cluster **A** (special-fn scalar dup) is independent of the migration but should be addressed to remove the scalar-vs-array drift risk.
